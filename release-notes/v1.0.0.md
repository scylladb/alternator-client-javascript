# @scylladb/alternator-client v1.0.0

This is the first stable release of the AWS SDK v3-compatible DynamoDB client
for ScyllaDB Alternator.

## Install

```sh
npm install @scylladb/alternator-client @aws-sdk/client-dynamodb
```

Applications using document commands must also install
`@aws-sdk/lib-dynamodb`.

The Node.js build requires Node.js 22 or newer. The integration suite for this
release uses ScyllaDB 2025.1 as its tested baseline; that is not a guarantee of
compatibility with every ScyllaDB release.

## Highlights

- Retains the AWS SDK v3 command, middleware, retry, waiter, and `destroy()`
  APIs while replacing a single AWS endpoint with Alternator seed discovery.
- Discovers live nodes through `/localnodes` and supports cluster, datacenter,
  and rack routing with explicit fallback chains.
- Provides low-level and document clients. The document client can either own a
  client created from Alternator configuration or wrap a caller-owned DynamoDB
  client.
- Ships Node.js and Edge builds. Node.js supports ESM and CommonJS consumers;
  browser and worker export conditions select the Edge implementation.
- Supports Node.js CA and mutual-TLS material, certificate verification,
  connection reuse, socket-pool tuning, request/connect/socket timeouts, and TLS
  session-cache control.
- Supports gzip request compression and gzip/deflate response decompression,
  with runtime-specific Web Streams support in Edge environments.
- Adds optional header whitelisting and a replaceable, appendable, or
  transformable ScyllaDB client user agent.
- Adds key-route affinity for supported DynamoDB partition-key values, automatic
  partition-key discovery, and deterministic `BatchWriteItem` coordinator
  voting.
- Handles IPv4 and IPv6 seeds and discovered nodes, with bounded DNS address
  fallback while contacting configured discovery endpoints.
- Moves retry attempts across the current node query plan when the AWS retry
  strategy classifies an error as retryable.

## Known limitations

- Node health is not quarantined persistently across requests. A failed node can
  be selected again until a later `/localnodes` refresh omits it.
- Topology changes are learned by scheduled, request-triggered, or manual
  discovery refreshes; the client does not subscribe to topology events.
- Custom TLS material, Node connection agents, and TLS session caching are not
  available in the Edge runtime.

See the [README](https://github.com/scylladb/alternator-client-javascript#readme)
for configuration and runtime details.
